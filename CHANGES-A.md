# CHANGES-A: orchestrate.py, harmonize.py, handoff.py

Files edited: `python/geminga/orchestrate.py`, `harmonize.py`, `handoff.py`, `tests/test_orchestrate.py` (fixture files renamed, see 1b), and the new `tests/test_fixes_orchestrate.py` (136 regression tests; each was written first and failed on the old code). `tests/test_hyvesta_additions.py` is unchanged. No other module was touched. **BEHAVIOUR** marks a change callers can see.

## 1. A piece declared local, then built, from another dataset's file (orchestrate.py)
- 1a **BEHAVIOUR** `_walk_for` matches `(?<![A-Za-z0-9])ACC(?![0-9])` (case-insensitive) on the file *stem* (name minus its data suffix), and keeps only files with a `_DATA_SUFFIXES` suffix, `.zarr` stores, and matrix directories (a dir holding `matrix.mtx[.gz]`, or a Cell Ranger bundle: `outs/`, `{filtered,raw}_feature_bc_matrix[.h5]`). Order is deterministic; hidden names and directories a build wrote (`blueprint.json` + `manifest.json`) are skipped. `resolve_pieces` now walks `search_dirs` once and uses a substring index, not one walk per piece. `GSE123456_other.h5ad` is not `GSE12345`, `SRR14487741.fastq.gz` is not `SRR1448774`, `atlas_figure.png` is not a dataset.
- 1b **BEHAVIOUR** `p.id` is a needle only when `find_accessions(p.id)` finds something. A file named after a non-accession piece id (`A_jurkat.h5ad`) is no longer picked up by `search_dirs`; use `attach()`, a catalog record, or put the accession in the file name. `tests/test_orchestrate.py` fixtures were renamed accordingly (`GSE00001_A_jurkat.h5ad`, `GSE00002_B_k562.h5`, `PRJNA000003_C_thp1_mtx`).
- 1c Vault members: `vault.find(needle)` stays the prefilter, then the same boundary rule is applied to the member path.
- 1d **BEHAVIOUR** `resolve_pieces` checks `os.path.exists` for catalog `local_paths`, catalog targets and `p.local`; a vanished path no longer makes a piece local. Catalog paths that sit in a puzzle directory (the build's own outputs, recorded by `note_local`) are never taken as sources.
- 1e **BEHAVIOUR** `build` tries `p.local` in turn (matrices before tables; first that opens), records every path as `candidates` (+ `candidate_errors`, + `opened` for a bundle) on the built piece and on an unreadable hole. Cell Ranger bundle directories open their `.h5` / matrix dir. `resolve(search_dirs="one/dir")` accepts a bare string.

## 2. GeneMap.canonical / align silently lose genes (harmonize.py)
- 2a **BEHAVIOUR** `canonical(name, "symbol")` accepts any name that is not junk and not shaped like an Ensembl/Entrez/HGNC id: `CD8A`, `P2RY12`, `B3GNT2` pass. UniProt typing is trusted only on a map hit. Lowercase `ensg…` is an id, not a symbol.
- 2b **BEHAVIOUR** Junk (empty, whitespace or `:` inside, starts with `Unnamed`, `nan`/`None`/`NA`/…) is unmapped, so `align` reports it. The Entrez fallback is unchanged.
- 2c **BEHAVIOUR** (new report keys) `align` report per piece: `n_duplicate` (first occurrence wins, later names mapping to the same id are counted, not summed), `duplicate_examples`, `panel_missing`; `n_in = n_mapped + n_duplicate + n_unmapped`. `Alignment.panel_missing` / `.panel_duplicates` hold the panel entries with no id in the key space / adding nothing new. `explain()` and the `Harmonizer.align` log show them.

## 3. Wrong-gene mapping (harmonize.py)
- 3a **BEHAVIOUR** (`len(gm)` counts genes, not rows) `GeneMap.add` stores its own copy and merges a record into an existing one with the same symbol (ids and aliases unioned, caller's object untouched). Records whose ids contradict (two Ensembl ids, human vs mouse) stay apart: they are different genes sharing a name.
- 3b `resolve(name, key=None)`: among symbol owners (else among alias owners) the first with a non-empty `key` wins; `canonical` and `to` pass the key.
- 3c **BEHAVIOUR** `expand` returns only symbol owners when any exist; a shared alias (a complex) still expands to every member. `members()` is unchanged. `to()` still gives one value per name (a complex maps to its first member; use `expand`).
- 3d **BEHAVIOUR** `from_table`: a multi-valued id cell on a single-gene row (`uniprot_ids="P04745|P0DUB6"`) keeps the first and aliases the rest; complex rows whose id lists do not pair up are still left blank.
- 3e Ensembl version suffixes are stripped wherever an id is stored (ids, aliases, `from_features`, `panel_table`), so `.12` and `.14` merge into one record.
- 3f **BEHAVIOUR** `align(panel=)`, `panel_table` (new `expand=True`; `expand=False` is the old one-row-per-entry form `build` uses for `var`) and `Orchestrator.coverage` expand complexes. In coverage a requested complex is evidenced by any member; `panel_genes` also works for `key="group"`.

## 4. build() provenance (orchestrate.py)
- 4a **BEHAVIOUR** Regions of an earlier build in the same `dest` that this build did not produce (targets `puzzle`) are dropped from the manifest and their files removed; other producers' regions stay. `overwrite=False` on a `dest` that already holds regions raises `ValueError` before anything is written (it used to clobber X files and fail at `var`).
- 4b The harmonizer log is reset at the start of each build, so `blueprint.json` carries this build's steps only.
- 4c **BEHAVIOUR** per built piece: `source_sha256` (source file; `matrix.mtx[.gz]` for a triple; first 256 MB for huge files, as `_sha256` already does) and `output_sha256`. `sha256` stays, with its old meaning (the output hash).
- 4d **BEHAVIOUR** A piece failing while streaming becomes a hole `unreadable` (reason in `note`); its X file is removed and its obs rows never reach `obs` (obs are staged per piece in a temp Arrow file and appended once the piece is whole: about 10 ms for 200k cells; leases are released). Table pieces fall through to the next candidate. The manifest and dispatch are written in a `finally` and match the disk (also for `KeyboardInterrupt`); a failed build leaves `blueprint.json` with `complete: false` and the error. Limitation: the axis is computed before streaming, so a piece that dies later is not removed from it retroactively.
- 4e **BEHAVIOUR** `build(..., allow_empty=False)`: `ValueError` ("share no features", with the alignment report) when the alignment has no features, or no piece keeps any of them (e.g. a panel nobody carries). Readers are closed first and nothing is written.
- 4f Real sheet/line numbers in `Piece.source`: xlsx blank rows no longer shift them; CSV is read with `csv.reader` so blank lines and multi-line cells keep true start lines (fully blank CSV rows are skipped, as in xlsx; blank headers become `colN`).
- 4g **BEHAVIOUR** Vanished file -> hole `missing`, printed "file missing" (`Puzzle.print_table` also never prints a hole as "here"). Also: piece ids are made safe file names (`X_<name>`, collisions suffixed), so an odd id cannot write outside `dest`; `Puzzle.measured()` / `to_anndata()` skip table pieces instead of raising; `Puzzle.read_X` follows the stored `roi`.

## 5. Facets (harmonize.py, orchestrate.py)
- 5a `read_descriptions(columns={"species": "Org", ...})` pins now reach the facets (`facets_of(columns=)`, `Harmonizer.facets(row, columns=)`); only explicit pins are routed, guessed columns behave as before.
- 5b **BEHAVIOUR** `_rows_from` turns None/NaN/NA into `""` for list, pyarrow, pandas, polars, JSON and xlsx input (no 'nan' tissue, no NaN `n_cells` crash; `_first_int` also returns None for NaN/inf). `Piece.row` holds `""` there.
- 5c **BEHAVIOUR** `disease`: `healthy` loses to any other hit; `ms` is a 2-character whole-word synonym (no plural, so not `mss`), "100 MS patients" still gives multiple sclerosis, `mssql`/`MS3SEG` do not.
- 5d **BEHAVIOUR** `perturbation`: technology synonyms beat effect words (`knockout`, `knockdown`, `dropout`, `overexpression`, `drug`, …), and `CRISPRa-style` is not a CRISPRa claim: "CRISPRi knockdown" is CRISPRi, "TF-ORF library (CRISPRa-style overexpression)" is still ORF overexpression.
- 5e **BEHAVIOUR** (`access`) `organisms(text)` lists all in text order; `organism()` is the first of them. `access`: `public` matches as a whole word ("publication" -> ''), `publicly`/`freely` added to open.
- 5f `facets_of(donor_keys=...)` fills the `donor` facet.

## 6. Accession and gene parsing (orchestrate.py)
- 6a **BEHAVIOUR** `find_accessions` uses alphanumeric boundaries (underscore delimits: `GSE12345_RAW.tar`, `data/GSE12345_counts.csv`, `SRR1448774_1.fastq.gz`), GSE/GSM/GPL/SRR/ERR/DRR/SRX/SRP/PRJ are case-insensitive and upper-cased, and PRIDE `PXD`, Synapse `syn`, `MTBLS`, `SRS/ERS/DRS`, `GDS`, `PRJCA`, `OMIX`, `EGAF` are recognised (kinds `pride synapse metabolights sra_sample geo_dataset gsa_project omix ega_file`). `resolve` gives them offline statuses (fetchable; `ega_file` controlled, `needs pyega3`; Synapse needs `synapseclient`). A literal-hint prefilter keeps `describe` at or below its old time.
- 6b **BEHAVIOUR** `_genes`: splits on `and`, `or`, `&`, `/`, strips parentheses and keeps the bracketed alias as its own token; qualifiers (KO, KD, WT, …) and `N/A` are dropped; an Entrez id needs 3+ digits, so `"12"` is no gene.
- 6c **BEHAVIOUR** Repeated CSV/xlsx/pandas/arrow headers become `Notes`, `Notes.1`, …, all searched for accessions.
- 6d Piece ids stay unique for `A, A, A_2` and every repeat (`A, A_2, A_2_2`); `Orchestrator.describe` also never overwrites an existing id.
- 6e **BEHAVIOUR** `_first_int(text, units)`: decision documented in the docstring. With units and no unit word, a bare number still counts (`"300"`, `"58,302 profiled"`, and the legacy `"100 MS patients"` size), but a number followed by a noun for something else (datasets, studies, cohorts, genes, antibodies, libraries, …) is skipped: `"44 datasets"` is None. Strict "no unit means None" was rejected: it would erase every bare CSV count.

## 7. Harvest (handoff.py)
- 7a **BEHAVIOUR** Region names must match `^[A-Za-z0-9._-]+$` (not all dots, <= 200) and the file must really land in the root (`realpath` check, so a symlink out of it is refused): `../escaped` raises `ValueError`. Checked before a view is loaded.
- 7b **BEHAVIOUR** Dict columns accept numpy, list/tuple (ragged nested lists -> list columns, no numpy detour), pandas/polars Series, pyarrow Array/ChunkedArray. In `add_table` anything else, scalars included, raises `ColumnTypeError` (a `TypeError` and a `ValueError`). `Harvest.add(view)` still drops the scalar metadata of a view's dict (`bin_size`).
- 7c npy `rows` is `shape[0]` (1 for 0-d). Sparse matrices keep their dtype (float64 stays) and `stat["shape"]`, `stat["dtype"]` are recorded (row/col are int64 only when needed); sparse + npy is an error.
- 7d **BEHAVIOUR** `add_staged(..., overwrite=False)` (new parameter, default no longer overwrites) refuses to replace a region; a name derived from the staging key is sanitised, an explicit one validated.
- 7e **BEHAVIOUR** A damaged manifest raises `ManifestError` (a `ValueError` and a `RuntimeError`) naming the file, instead of loading as 0 regions and being overwritten.

## 8. Thin list
- 8a **BEHAVIOUR** `_table_piece`: a column counts as gene-shaped only on a map hit, a `SYMBOL (entrez)` header, or an Ensembl/Entrez id, not because `canonical` returned it as itself. A long hit table with Gene/Score/FDR/… columns stays long (`gene_symbol` added); wide DepMap-style tables still detect. The writer is closed on failure.
- 8b `Orchestrator.save()` writes the gene records and column synonyms (schema `geminga.pieces/2`); `load()` restores them (and still reads old files, with an empty map), so a reloaded orchestrator builds the same puzzle.
